### PROJECT: Short, explicit ticket title


> **Labels:** `backend`, `frontend`, `devops`, `api`, `ux`, ...
>
> **Type:** `Feature` / `Bugfix` / `Task` / `Enhancement` / `Technical Debt` / `Hotfix` / `Epic` / `Refactor` / `Story` / `Documentation` / `Security` / `Spike` / `Integration` / `UI/UX`
>
> **Priority:** `Urgent` / `High` / `Medium` / `Low`
>
> **Efforts:** `1` / `2` / `3` / `5` / `8` / `13`
>
> **Status:** `Ideas`
>
> **Size:** `XS` / `S` / `M` / `L` / `XL`
>
> **Estimate:** `- hours`

---

### 1. Summary

One or two sentences summarizing the need or problem, understandable by someone unfamiliar with the detailed context.

---

### 2. User Story

As a **[user type / role]**,
I want **[action or need]**,
so that **[benefit / business goal]**.

---

### 3. Context / Background

- Why does this ticket exist now?
- What business or technical problem does it solve?
- Links to discussions, specs, mockups, related tickets, incidents, etc.

---

### 4. Detailed Description

Full description of the need: expected behavior, functional scope, use cases covered and not covered, impact on existing
modules.

**Out of scope:**

- Item A not handled in this ticket
- Item B deferred to a future ticket

---

### 5. Acceptance Criteria

- [ ] Given [context], when [action], then [expected result]
- [ ] Given [context], when [action], then [expected result]
- [ ] The following edge cases are handled: ...
    - Case 1: ...
    - Case 2: ...
- [ ] Error messages/validations comply with UX specs
- [ ] Performance stays within defined thresholds (if applicable)

---

### 6. Technical Notes

- Planned technical approach / impacted architecture
- Relevant API endpoints (method, route, expected payload)
- Data models / migrations required
- Technical dependencies (libraries, third-party services, other tickets)
- Points of attention (security, performance, backward compatibility)

---

### 7. Mockups / Visual References

- Figma link / screenshots
- Flow or sequence diagrams if relevant

---

### 8. Test Plan

| # | Scenario | Expected Result | Type (manual/auto) |
|---|----------|-----------------|--------------------|
| 1 |          |                 |                    |
| 2 |          |                 |                    |

---

### 9. Dependencies

- Blocked by: `#TICKET-ID`
- Blocks: `#TICKET-ID`
- Related to: `#TICKET-ID`

---

### 10. Risks & Open Points

- Identified risk 1 - mitigation considered
- Open question requiring a product/technical decision

---

### 11. Definition of Done

- [ ] Code developed and reviewed (PR approved)
- [ ] Unit / integration tests written and passing
- [ ] Technical documentation updated (README, wiki, changelog)
- [ ] Acceptance criteria validated in UAT
- [ ] Deployed to test / staging environment
- [ ] Approved by reporter or Product Owner
- [ ] No regression detected

---

### 12. Attachments

- Logs, screenshots, exports, config files, etc.
